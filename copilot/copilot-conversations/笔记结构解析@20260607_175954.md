**ai**: 配置 OpenCode 时，以下几个细节值得特别留意（根据你的笔记整理）：

### 1. 网络与代理
- WSL 环境下如果直连下载失败，需要临时或永久配置代理。建议用 `ip route` 获取 Windows 主机的 IP，在 `~/.bashrc` 中写入 `http_proxy` / `https_proxy` 环境变量。混合端口可以在 Clash Verge 中查看（如 7890）。[^1]
- 使用 `curl ipinfo.io` 测试代理连通性后再执行安装脚本。[^1]

### 2. 会话目录绑定 —— 最容易踩坑
- **不要在深层子目录启动 OpenCode**。例如 `cd project/backend && opencode` 会导致会话绑定到该子目录的绝对路径。一旦改名或移动文件夹，之前的会话就会丢失。[^1]
- **推荐做法**：在项目根目录（如 `cd project_root && opencode`）启动，之后 Agent 可以自由操作子目录，终端里手动 cd 即可。项目根目录尽量固定不重命名、不移动。[^1]

### 3. MCP 配置
- 确保 Node.js ≥ 18、OpenCode ≥ 1.14。[^2]
- 配置文件位于 `~/.config/opencode/opencode.json`，支持本地 MCP（如 `shadcn`）和远程 MCP（如 `context7`）。配置后建议预热 npx 缓存，避免首次加载失败。[^2]
- 验证日志：`rg "mcp.*shadcn" ~/.local/share/opencode/log/...`，应有 `service=mcp key=shadcn type=local found` 且无 `Connection closed`。[^2]

### 4. 重装 Ubuntu 时的环境清理
- 如果遇到难以解决的问题，可以用 `wsl --unregister Ubuntu` 彻底重装。[^1]
- 重装后建议**关闭 Windows 路径继承**：在 `/etc/wsl.conf` 中写入 `appendWindowsPath = false`，避免 WSL 的 `$PATH` 被 Windows 环境变量污染。[^1]

### 5. 其他实用习惯
- 使用 `source ~/.bashrc` 刷新配置、`opencode --help` 验证安装成功。[^1]
- `AGENTS.md` 可以写在项目根目录，用来指导 Agent 行为，但官方更推荐通过调整工程架构来提升效果。[^1]
- Skills 分为全局（`~/.config/opencode/skills/`）和项目（`.opencode/skills/`），可以用 `/skill` 命令检查是否加载成功。[^1]
